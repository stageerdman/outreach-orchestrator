Outreach Orchestrator — known issues and TODOs
Running list. Resolved items move to the relevant update's wiki.md.

- [ ] 2026-11-11 WhatsApp only matches 1:1 chats (phone or `@lid` ids);
      group chats are missed. CRM phones now come from `phone_e164`, but a
      contact without it (1 of 144) won't match.
- [ ] 2026-11-11 Email refresh reads every message header in Inbox, Sent and
      Archive each time. Fine for this mailbox (~90 messages); revisit if it
      grows to many thousands.
- [ ] 2026-11-11 Which WhatsApp chats are fully fetched is kept in memory, so
      after a server restart the first refresh re-asks the phone once per
      chat (~3 min in the background for 60 chats).
- [ ] 2026-11-11 The WhatsApp bridge only runs while Outreach.app is open, so
      new messages sync only then (WhatsApp delivers missed ones on reconnect).
      Add it as a login item if that becomes a problem.
- [ ] 2026-11-11 "Open WA" marks a draft as sent as soon as WhatsApp opens;
      if the message isn't actually sent there, it's only visible as missing
      after the next refresh.
- [ ] 2026-11-11 Approving an AI request doesn't complete the CRM task
      (the app is read-only towards ResultsON).
- [ ] 2026-11-11 "Has WhatsApp" is a guess: a number counts only if the
      bridge has a WhatsApp id (lid) or a chat for it. A new lead the phone
      has never seen may have none yet and gets email instead. Definitive fix:
      a bridge endpoint using whatsmeow's IsOnWhatsApp (vendor patch, needs
      approval).
